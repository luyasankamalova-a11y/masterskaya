# Моя Мастерская — этап 0

Личный инженерный мир: знания, исследования, объекты, материалы, рисунки, идеи и проекты
как единая система объектов и связей. Рядом — Сириан, звёздный феникс, который помогает думать,
но никогда не меняет Мастерскую без твоего «да».

Архитектура (источник истины) — отдельный документ «Моя Мастерская — Архитектура».

## Запуск

Нужен Node.js 20.11 или новее (лучше 22).

```bash
npm install                        # или npm ci, когда в репозитории есть package-lock.json
npx playwright install --with-deps chromium   # один раз, браузер для тестов
npm run dev          # http://localhost:5173 — разработка
npm run check:deps   # все импортируемые пакеты объявлены в package.json
npm run typecheck    # настоящий TypeScript + @types/react
npm run build        # сборка PWA в dist/
npm run preview      # собранная версия: http://localhost:4173
npm test             # тест ядра (настоящий Dexie) + сборка + сквозной тест интерфейса
```

Что проверяют тесты:
- `npm run test:core` — `tests/core.journey.ts` в Chromium: путь объекта «идея → исследование →
  материал → тема → эскиз → проект», «Неразобранное», каскадное удаление, архив, поиск, экспорт/импорт (35 проверок).
- `npm run test:e2e` — `tests/e2e.mjs`: весь сценарий этапа 0 через интерфейс (мышь, касания, стилус)
  и проверка того, что реально записано в IndexedDB, плюс отсутствие ошибок в консоли (63 проверки).

Каждый запуск тестов начинается с чистого состояния: Playwright открывает новый временный профиль
браузера, а тест сам проверяет, что база пуста. Данные, созданные вручную в твоём браузере, на тесты не влияют.

Если зависимости или браузер не установлены, скрипты проверок завершаются с ошибкой
и пишут, чего не хватает. Об успехе они сообщают, только если проверка действительно выполнилась.

## package-lock.json

Lock-файл пока не создан: в среде, где разрабатывался этап 0, доступ к реестру npm закрыт,
а придумывать версии и контрольные суммы вручную нельзя. Получить его можно двумя способами:
- на своём компьютере: `npm install` — файл появится рядом с package.json, его нужно закоммитить;
- через GitHub Actions: первый запуск workflow без lock-файла выполнит `npm install`
  и выложит готовый `package-lock.json` артефактом «package-lock» (страница запуска → Artifacts).
  После коммита этого файла workflow будет ставить зависимости через `npm ci`.

## GitHub Actions

`.github/workflows/deploy.yml` на каждый push и pull request: установка зависимостей (`npm ci`
при наличии lock-файла) → `check:deps` → `typecheck` → `build` → Chromium для Playwright → `npm test`.
`dist` публикуется на GitHub Pages только с ветки main и только если все проверки прошли.

## Как проверить, что данные сохраняются

1. Открой приложение, зайди в «Мою мастерскую», нажми «Положить первую мысль», сохрани идею.
2. Перетащи узел в другое место.
3. Перезагрузи страницу (или закрой вкладку и открой снова) — идея на том же месте.
4. Данные лежат в IndexedDB этого браузера: DevTools → Application → IndexedDB → `masterskaya`
   (демо — отдельная база `masterskaya-demo`).
5. Резервная копия: ⚙ → «Экспорт всей Мастерской» → файл `.json`. Вернуть — «Импорт из архива».

## Как проверить на планшете

**Быстро, в одной Wi-Fi сети:** `npm run dev`, в терминале появится адрес вида
`http://192.168.x.x:5173` — открой его в браузере планшета. Работает всё, кроме установки
как приложения и офлайна (для них браузер требует https).

**Как настоящее приложение (рекомендуется):**
1. Создай репозиторий на GitHub и загрузи туда проект.
2. Settings → Pages → Source: **GitHub Actions**. Файл `.github/workflows/deploy.yml` уже есть:
   при каждом push в main он проверит проект и, если всё прошло, опубликует его по адресу
   `https://<логин>.github.io/<репозиторий>/`.
3. Открой адрес на планшете → «Поделиться» → «На экран „Домой“» (iPad) или «Установить приложение» (Android/Chrome).
4. После первого открытия Мастерская работает и без интернета.

Netlify тоже подходит: Build command `npm run build`, Publish directory `dist`.

**Что проверить на планшете:** один палец двигает карту, два — масштабируют; долгое нажатие на узел —
меню; двойное нажатие — открыть; стилусом от узла к узлу — связь; в Студии стилус рисует с нажимом,
ладонь на экране не мешает, палец двигает холст.

```

  core/        ядро: модель, реестр типов, Dexie, commit(), действия, запросы, синхронизация

  spaces/      мир и пространства (карты), лотки Библиотеки

  shell/       верхняя полоса, «＋», поиск, карточка объекта, меню, настройки
  sirian/      Сириан: канон, контроллер состояний, рендерер, наблюдатель роста идей
  ai/ voice/   границы будущих AI и голоса (сейчас не подключены)
  files/ search/ store/ app/ styles/
tests/
  core.journey.ts   тест ядра: путь объекта идея → проект (35 проверок)
  run-core.mjs      запуск теста ядра в Chromium
  e2e.mjs           сквозной тест интерфейса и базы (63 проверки)

```

## Про `tools/offline/`

Этап 0 разрабатывался в среде, где доступ к реестру npm закрыт. Поэтому `npm install`
и проверки с настоящими Vite, Dexie, Zustand и @types/react там не выполнялись.
Для этой среды есть отдельный набор, `npm run check:offline` (или `node tools/offline/check-all.mjs`).
Первым шагом он запускает `check:deps` — эта проверка не зависит от заглушек.

| Шаг | Чем выполняется | Отличие от настоящей проверки |
| --- | --- | --- |
| Проверка типов | `tools/offline/typecheck.mjs` | Заглушка типов React вместо @types/react; пропускаются только ошибки TS7006 в параметрах обработчиков `onXxx={(e) => …}` |
| Сборка | `tools/offline/build.mjs` (esbuild) | Заглушки `dexie` и `zustand`, если настоящих нет; свой простой service worker вместо vite-plugin-pwa |
| Тест ядра | `tests/run-core.mjs` | Заглушка `dexie`, если настоящего нет |
| Сквозной тест | `tests/e2e.mjs --serve dist-offline` | Работает на офлайн-сборке |

Предварительные условия: Node.js 20+ и пакеты `typescript`, `esbuild`, `react`, `react-dom`, `playwright`
плюс браузер Chromium для Playwright. Скрипты ищут пакеты в `node_modules` проекта,
затем в `/opt/npm-tools/node_modules` (так было в среде разработки), либо в папке,
указанной в `MASTERSKAYA_NODE_MODULES`. Если чего-то нет — шаг помечается «НЕ выполнена»
и набор завершается с ошибкой.

Код приложения импортирует настоящие `dexie` и `zustand`. После `npm install` заглушки не нужны,
папку `tools/offline/` можно удалить.
